Sistema visual — SaaS Inventory

Dirección derivada de las referencias del usuario (SaaS administrativo claro, superficies blancas sobre gris frío, azul único de acento, tarjetas discretas, iconografía lineal tipo iOS) y adaptada a los principios de Apple Human Interface Guidelines. Todos los valores se exponen como --color-* / --radius-* / --space-*: cambiar el acento o el fondo en el futuro es una edición de tokens, nunca de componentes. Alterna el chip Tema para ver light y dark.

Principios HIG aplicados

Claridad

Jerarquía tipográfica evidente, números tabulares, la acción primaria siempre reconocible por color y posición.

Deferencia

La interfaz acompaña a los datos: gris neutro, un solo acento, sin ornamentación. Las tablas son el protagonista.

Profundidad

Solo dos sombras. Separación por borde y fondo antes que por sombra. La profundidad comunica navegación (riel, drawer, diálogo).

Consistencia

Un registro de navegación, mismos badges semánticos en todos los módulos, mismos controles para las mismas acciones.

Feedback

Todo control tiene hover / pressed / focus / disabled / loading. Estados combinan color + icono + texto.

Divulgación progresiva

Primero lo esencial; el detalle se revela al tocar la fila, abrir el drawer o expandir el riel.

Manipulación directa

Steppers, edición de precio en línea, búsqueda con resultados inmediatos en la Nueva venta.

Táctil

Objetivo mínimo 44×44 en tablet y móvil; controles a 44–48 px de alto fuera del desktop.

Configuración

Fondo --nav-bg = primary. Colapsado 68 px → expandido 232 px con :hover / :focus-within, transición 160 ms de width + opacity. El panel expandido se superpone (posición absoluta): la columna de contenido nunca se desplaza. Vuelve a colapsar al salir el puntero. El estado activo se ve incluso colapsado (superficie clara translúcida nav.active + barra izquierda blanca de 3 px). Respeta prefers-reduced-motion. Tablet: riel permanente + botón de fijar (superposición + scrim). Móvil: botón de menú → drawer con el mismo fondo primary.

Modo claro / oscuro

FASE 17: solo LIGHT MODE. El mapa de tokens ya está preparado para dark (solo se redefine :root[data-theme="dark"], incluidos los --nav-*) y este artboard lo demuestra con el chip Tema — pero el theme switcher, la persistencia del tema y el QA completo de dark quedan DIFERIDOS / FUTURE. Los tokens se conservan como prueba de extensibilidad, no como feature comprometida de FASE 17.

Elementos de referencia — no comprometidos en FASE 17

Algunos artboards muestran elementos que no tienen contrato backend y por tanto NO obligan a FASE 17 a implementarlos: búsqueda global del header, campana / notificaciones, botón Exportar, y todos los KPIs / gráficos agregados de Home e Historial (analítica → FASE 18 — Dashboards & Reports). Aparecen como referencia visual marcada PROTOTYPE ONLY. FASE 17 no crea endpoints agregados, no calcula KPIs en cliente y no carga todas las ventas para métricas; el Home se mantiene simple hasta FASE 18. Regla general: FASE 17 no crea botones muertos — un control sin soporte real se retira o se marca FUTURE.
